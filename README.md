# SteamBooster Decky

SteamBooster для Steam Deck и Decky Loader: каталог игр, оригинальный сценарий «Оцени аккаунт», пополнение баланса и предложения покупки на страницах Steam Store.

**v0.1.0 — предварительная версия.** Сборка, автоматические проверки и взаимодействие оригинальных компонентов проверены. Проверка на физическом Steam Deck ещё требуется. Оценка зависит от доступности соответствующего события на SteamBalance; завершённое событие может показывать сообщение об окончании.

## Установка на Steam Deck

1. Установите [Decky Loader](https://github.com/SteamDeckHomebrew/decky-loader) и войдите в Steam.
2. Скачайте ZIP из [Releases](https://github.com/Hokage-git/steambooster-decky/releases). Это архив плагина Decky; распаковывать его вручную не требуется.
3. В настройках Decky включите режим разработчика, если пункт установки из ZIP/URL скрыт. Установите ZIP либо укажите прямую ссылку на архив релиза.
4. Откройте SteamBooster в панели быстрого доступа Decky. Дождитесь состояния «Подключено».
5. Если ранее установлен SteamBooster Linux, отключите его сервис перед использованием плагина. Два моста одновременно не запускаются.

Плагину не нужны отдельная установка Node.js, системный сервис SteamBooster или изменение системных разделов SteamOS. Используются Python и aiohttp из среды Decky.

## Как пользоваться

- **Каталог игр** открывает оригинальный каталог внутри страницы Decky. Поиск, фильтры и покупка используют сайт SteamBalance и текущий аккаунт Steam.
- **Оцени аккаунт** открывает оригинальный сценарий и передаёт библиотеку/инвентарь через исходный сборщик SteamBooster. Управление розыгрышами не добавлено.
- **Пополнить баланс** показывает оригинальную форму в интерфейсе Decky. Платёжный переход открывается в браузере Steam.
- **Магазин и предложения игр** открывает Steam Store. Веб-компонент SteamBooster добавляет предложения на подходящих страницах игр.

Внутри страницы плагина выделите область страницы: направления выбирают элементы, A нажимает, B возвращает назад. Также доступны кнопки «Предыдущее», «Следующее», «Нажать». Для выбранного поля появляется стандартное поле Decky с экранной клавиатурой; введите значение и нажмите «Применить». Тачскрин и трекпад остаются доступны.

Обычная ссылка карточки каталога открывает страницу игры через навигацию Steam. Кнопки покупки остаются в оригинальном сценарии. Плагин автоматически не повторяет оплату или активацию после таймаута: результат такой операции может быть неизвестен.

## Восстановление и удаление

- «Ожидание интерфейса Decky» — перейдите в игровой режим, откройте Decky и SteamBooster.
- «Другой мост активен» — отключите Linux-лаунчер SteamBooster, затем нажмите «Восстановить подключение».
- «Steam недоступен» — убедитесь, что Decky Loader работает и доступен его локальный CEF debugging на 127.0.0.1:8080. Восстановите подключение; если отладочный порт недоступен после обновления Steam, перезапустите Steam/Decky в удобное время. Плагин сам Steam не перезапускает.
- Если страна магазина не определяется, откройте Steam Store → сведения об аккаунте; компонент захватит страну текущего аккаунта.
- Переключатель «Включён» останавливает мост и сохраняет выбор. Для удаления используйте меню плагинов Decky. При выгрузке освобождаются собственные соединения, обработчики и встроенные формы.

Состояние включения и страны аккаунтов сохраняются в каталоге настроек плагина Decky. Настройки оригинальной формы сохраняются локально в Steam. Ключи, токены и полный инвентарь в журналы плагина не записываются.

## Проверка на устройстве

См. [список проверок](docs/device-test.md). В первую очередь: установка и запуск в Game Mode, управление каталогом, оценка аккаунта, предложения на странице игры, сон/пробуждение, перезапуск Steam и выключение плагина. Реальные оплаты и активация не выполнялись в автоматических проверках.

## Сборка для разработчиков

Нужны Node.js 24+, pnpm 9 и Python 3.10+:

```sh
corepack pnpm install --frozen-lockfile
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/build_release.py --output-dir out
```

Если Corepack отсутствует, используйте `npx --yes pnpm@9.15.9` вместо `corepack pnpm`. Готовые JS-компоненты включены в репозиторий; Bun и исходники Linux-проекта нужны только при обновлении этих компонентов.

## Синхронизация с Linux-приложением

Начальная версия зафиксирована на `steambooster-linux` commit `0b462bb853acb54540c1d65a68cac2f6061f9e06` (v1.1). Framework 1.0.2, checkout/addfunds 1.0.2, rateaccount 1.0.0. Источники, версии, хеши сборок и применённой правки записаны в `vendor/manifest.json`.

Правка `patches/0001-frozen-api-plugin-outcomes.patch` хранит результаты инициализации в замыкании вместо записи в замороженный API. Защита API сохраняется. Она нужна для проверки готовности и диагностики запуска плагинов.

Для обновления получите две рабочие копии исходного Linux-репозитория на зафиксированном commit. Первую соберите по инструкции Linux-репозитория. Во второй примените правку и соберите framework:

```sh
git -C patched-linux apply /path/to/steambooster-decky/patches/0001-frozen-api-plugin-outcomes.patch
bun install --cwd patched-linux/source/booster-framework
bun run --cwd patched-linux/source/booster-framework build
python3 scripts/sync_vendor.py /path/to/built-linux --patched-source /path/to/patched-linux
```

Скрипт проверяет commit и точное содержимое правки. При переходе на новую upstream-версию обновите pin, пересмотрите правку и выполните проверки. Публикация в магазине Decky не выполнялась; ZIP распространяется через GitHub Releases.

## Архитектура

`src/` — панель и адаптер окон Game Mode; `backend/` — транспорт CDP, поколения соединений, веб-мост и контроллер полей; `main.py` — жизненный цикл Decky. SharedJSContext сохраняет оригинальные сборщики Steam. Панель помечает реальный контекст Decky, поэтому подключение не зависит от заголовка настольного окна. Формы и каталог используют существующие компоненты; отдельные платёжные страницы открываются через Steam Navigation.

Запросы сайта разрешены только точному origin `https://steambalance.cc`. Сетевые запросы native-моста требуют токена включённого плагина и разрешённого HTTPS-хоста. Очереди ограничены, таймауты конечны, ответы старым контекстам после навигации отбрасываются. Работа обоих мостов одновременно блокируется.
